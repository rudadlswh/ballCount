# 라이브 액티비티 원격 시작 검증

경기 시작은 서버가 APNs의 ActivityKit `start` 푸시로 요청합니다. iOS 17.2 이상에서 앱 화면을 열지 않고 라이브 액티비티를 시작할 수 있습니다.

## 적용

- 서버의 `ApnsPushService` 변경을 배포합니다. 시작 페이로드의 `alert`, `attributes-type`, `attributes`, `content-state`가 모두 필요합니다.
- 새 앱 빌드를 설치하고 한 번 실행해 응원팀과 시작 토큰을 등록합니다. 앱 설정의 라이브 액티비티, 경기 시작 시 자동 시작, 경기 시작 알림 및 시스템 권한을 켭니다.
- Debug 등록 URL은 `KBO_BACKEND_BASE_URL`의 `/devices/register`를 사용하고, ActivityKit 등록 URL은 여기에서 파생합니다. 실제 기기에서 접근 가능한 백엔드 주소를 사용합니다.
- APNs 자격 증명, 앱 번들 ID와 토큰의 sandbox/production 환경이 맞아야 합니다.

## 실기기 확인

1. 서버 로그에서 `[LiveActivityStart] push-to-start token registered`와 허용 상태를 확인합니다. 토큰 원문은 로그나 문서에 기록하지 않습니다.
2. 앱을 앱 전환기에서 종료하고 응원팀의 새 경기 시작을 기다립니다.
3. 서버의 `[LiveActivityStart] APNs result`에서 `sent=1`을 확인합니다. 이미 원격 시작이 전송된 경기 키는 중복 방지로 다시 전송되지 않습니다.
4. 앱을 직접 열지 않은 상태에서 잠금화면·다이나믹 아일랜드가 나타나는지 확인합니다.
5. 앱 로그의 `source=remoteStart` 갱신 토큰 등록을 확인하고, 다음 이닝·득점 업데이트 및 경기 종료가 APNs로 반영되는지 확인합니다.
6. 자동 시작을 끄거나 응원팀을 변경한 다음 서버의 등록 상태가 최신 설정과 일치하는지 확인합니다.

- 기기: iPhone 15 Pro, iOS 27.2 (24B5089g), 개발자 모드 활성화.
- 앱: 개발 서명 Debug 빌드, `com.chogm.kboScore`. 테스트 동안 현재 Mac IP로 등록 URL을 빌드 인자에서만 덮어썼습니다. 저장된 기본 설정은 변경하지 않았습니다.
- 준비: 응원팀 롯데, 알림 허용, 라이브 액티비티·자동 시작·경기 시작 알림 활성화. 토큰 원문은 결과에 기록하지 않았습니다.
- 종료: iPhone 미러링의 앱 전환기에서 볼카운트 카드를 위로 밀어 종료했습니다. 시작 전 프로세스 목록에서 메인 앱 실행 파일이 없음을 확인했습니다. 확장 프로세스는 남아 있었습니다.
- 전송: 테스트용 가상 경기 UUID와 이 기기의 토큰만 사용했습니다. 실제 경기 데이터 변경, 다른 기기 대상 전송, 서버 배포는 하지 않았습니다. 백엔드 빌드의 `ApnsPushService.sendLiveActivityStart/Update/End`를 임시 로컬 하네스에서 호출했습니다.

### 발견한 환경 불일치

앱 서명의 `aps-environment`는 `development`, 앱이 등록하려는 환경 값은 `sandbox`였으나 이 기기에서 얻은 시작·갱신 토큰은 `production` APNs에서만 수신했습니다. 이전 설치의 토큰 캐시 영향인지 OS 동작인지는 확인하지 않았습니다. 이 결과만으로 전체 Debug 기본값을 운영 환경으로 바꾸지 않았습니다.

이번 성공은 **이 기기에서 확인된 운영 토큰을 운영 APNs에 전송한 경우**입니다. 개발·운영 토큰 환경을 자동으로 교차 재시도하도록 제품 코드를 바꾸지는 않았습니다. 새 설치 또는 운영 서명 빌드에서 토큰 환경과 등록 값이 일치하는지 추가 확인이 필요합니다.

테스트 종료 후 임시 토큰 기록 코드를 원래 소스로 복원하고 다시 서명 빌드했습니다. 기기의 Documents 파일 목록이 비어 있음을 확인했고, Mac의 임시 토큰 JSON 사본도 제거했습니다. 커밋하지 않았습니다.
